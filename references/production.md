# 生产流程与运行协议（production）

本文件是多阶段运行流程、材料批准、状态机、版本失效与交付命令的权威维护位置（由 SKILL.md 路由至此；SKILL.md 只保留摘要与指针）。规则只在此维护一份，提示词与模板中的相关表述均为应用层摘要，口径冲突时以本文件为准。

适用读者：主 Agent（规划、派发、汇总、交付）。切片写作者**不需要**读本文件，其任务包清单与执行口径见 `prompts/subagent_prompt.md`。

---

## 一、 问题链设计原则（规划期题型判定）

问题驱动的核心是让学生先遇到可观察的现象，再用问题、解释和证明逐步命名与概括它。引例可以来自历史、数学、物理或日常生活，但必须导向本节明确的数学任务；反例必须改变可识别的条件并说明被破坏的性质。凡涉及学生无法凭既有知识操作的新对象、新运算或新记号，必须先给出最小必要定义。

所有任务使用同一套规则和同一验收标准，不设置 P0/P1/P2 或其他等级。先完成原文映射、依赖检查和覆盖记录，再按记录生成题链；每个节点只保留能完成其学习目标的内容，其他内容删除并在覆盖表说明原因。

问题链不得按固定模板机械循环。先恢复原材料的知识顺序和论证依赖，再为每个知识单元执行下列固定题型判定；不满足条件的题型不得添加。

1. **进入题（Entry）**：用直观熟悉的具象对象、图示或最小计算实例暴露数学现象。
2. **辨认题（Identify）**：分类、填空、判断或读图，引导学生自主捕捉并确认结构共性。
3. **构造题（Construct）**：要求学生亲自动手构造、画图、列举满足特定条件的对象。
4. **反例题（Counterexample）**：变动某一约束条件，引导学生寻找失效反例，体会条件的必要性与概念边界。
5. **微型知识点（Microknowledge）**：**（在学生完成前置探究后插入，或在后续题需要新概念前穿插）** 一张 microknowledge 卡解决一个当前必需的定义、记号或运算。保留对象、条件和必要公式，优先简短；不以固定行数删掉数学条件或缩小字体。已经在前文建立的结论放入反馈或 knowledgebox，不重复包装成新定义。
6. **形式化题（Formalize）**：引导学生将自然语言直觉抽象为带全称量词 $\forall$、存在量词 $\exists$ 的严密数学表达。
7. **迁移题（Transfer）**：变换集合载体（如从数集迁移到矩阵群、置换群或函数空间），检验概念普适性。
8. **证明/综合题（Proof & Synthesis）**：调用前面逐步建立的判定条件与引理，完成命题严谨推导。证明支架按方法的新颖程度配置。首次遇到的方法可给关键障碍或必要中间目标；已有示范的方法可只给证明目标。策略段和分步题干不重复交代同一完整证明路线。核心论证不得遗漏，但不要求每个证明都同时包含策略段、多问和填空。
9. **回看题（Review）**：一句话提炼核心判据，反思内在联系，并铺垫承接下一小节。

### 内容块判定

- `discussion`：仅在能导向本节明确数学任务时使用，并在同一节写出讨论落点；否则不写。
- `exposition`：删去会损失动机、精度或跨节连贯性时保留；否则删除。
- `proofstrategy`：证明支架按方法的新颖程度配置（口径同上）。策略段和分步题干不重复交代同一完整证明路线。
- `knowledgebox`：**每节末必须**总结已建立的判据、适用条件、限制和下一节接口；不放尚未讲解的定义。

引例、反例和历史材料不是装饰项：每一项都要在 `coverage-map.md` 或章节总览中写明它改变了哪个判断、暴露了哪条边界或支撑了哪一步证明；无法说明功能时删除。若原材料中缺少能承担功能的引例或反例，可补充带明确来源和数学功能说明的材料，严禁编造来源。对话块同样适用：纯气氛对白不进入正文。

## 二、 生成前协议（强制）

任何生成任务必须先建立三个内部产物，之后才可写题目：

1. **原文骨架表**：按原文实际顺序列出每个定义、记号、例题、命题、证明和结论，并记录来源页或行号。原文顺序用于**溯源**；学案的教学顺序在尊重用户要求和论证依赖的前提下决定，凡偏离原文顺序必须在覆盖表记录理由，不得以“适合出题”为理由无理由提前或合并。
2. **依赖表**：对每个节点列出学生在动笔前必须知道的对象、运算、维数条件、记号和前置结论。依赖未闭合时，先补材料或拆分单元，不得直接出题。依赖一律按**学生实际可见内容**检查：仅在教师版出现的结论不构成学生侧依赖闭合。
3. **覆盖与变更表**：记录每个原文节点在学案中的位置、对应问题或材料、是否删改及理由。原文证明必须保留结论和关键论证链，删去内容必须可追溯。
4. **揭示顺序表（可并入覆盖表）**：对原材料中用 `\pause`、分页或讲稿动作实现延迟揭示的节点，识别其中的问题、观察、提示、答案与后续概括，记录**信息首次可见位置**；静态输出必须保留先判断、后反馈的次序，不得把答案提前并入背景叙述。

每个学习单元必须形成“材料/定义 → 最小示例 → 可完成的问题 → 反馈 → 下一节点”的闭环。问题可以促进发现，但不能让学生猜测尚未定义的新对象、新运算和新记号；“先探究后定义”只适用于学生能够凭既有知识完成的观察。

问题设计检查四点：顺序正确、依赖闭合、每题只有一个主要认知动作、答案能显示学生是否掌握目标。不要为了凑齐题型而制造反例、迁移题或形式化题。

### 固定执行顺序（不得跳步）

处理一份新材料时，严格按以下顺序执行。每一步有明确产物；产物未完成，不得进入下一步：

1. **读取原文**：按文件顺序读取全部材料，不只读取标题、目录或局部片段。
2. **建立 `source-map.md`**：每行记录 `编号 | 原文锚点 | 原文内容类型 | 核心陈述 | 所需前置 | 后续用途`。内容类型只能从“定义、记号、运算、例题、性质、命题、证明、结论、背景”中选择；启用对话层时另允许 `dialogue-hook`，字段为：`section/qid | 触发现象 | 角色功能 | 学生可见动作 | 暂不揭示的信息 | 后续承接节点 | 来源`。
3. **建立 `dependency-map.md`**：每行记录 `节点编号 | 必须先知道什么 | 学案中首次出现位置 | 是否已闭合`。任何“否”都必须先补材料或调整顺序。
4. **建立 `coverage-map.md`**：每行记录 `原文节点 | 学案位置 | 学习目标 | 对应问题/材料 | delivery_role | practice_mode | carrier_qid | planned_minutes | 是否同知识点首题 | 预计时间 | 推荐讲法 | 易错点 | 来源`。题目字段增加 `delivery_role`（core/support/self-study/reference）、`carrier_qid`（若此题承载多个原文节点则填写主载体题号）和 `planned_minutes`（学生预期完成时间）。没有对应记录的原文核心节点不得删除。
5. **设计学习单元**：只按三张表的顺序编写。每个单元先写材料和最小示例，再写问题、提示、答案和教师批注；问题类型按目标选择，不按清单凑数。**优先确定 delivery_role，确保 core 任务不超过预算限制**。启用对话层时：
6. **内容审校后再排版**：逐题检查来源锚点、依赖闭包、维数/记号、证明链和答案可解性；可为审读制作 TeX 草稿，但只有通过内容审校与独立教学验收（步骤 4.5）后才装配为最终 PDF 交付。

遇到材料过长时，仍按文件顺序分段读取；先完成全局 `source-map.md`、`dependency-map.md` 和 `coverage-map.md`，再起草。任何执行者不得自行创造替代台账或改变全局顺序。若依赖无法确定，标记为“待审”，停止该节点并先补齐依赖记录。

### 问题生成的最小决策树

对每个原文节点依次判断：

1. 学生是否需要一个新定义、记号或运算？需要则先写材料卡和最小例子。
2. 学生能否用已有材料完成一个确定动作？不能则补前置或拆题；补齐前置后仍不能完成则删除该题。
3. 该节点的目标是计算、辨认、解释、反例、形式化、证明还是迁移？只选择对应的一种主要动作。
4. 后续题是否依赖本题答案？依赖则在本题后加入**学生可见**的反馈、核对材料或后续概括，再进入后续题；仅在教师版出现的参考结论不构成依赖闭合。
5. 是否改变了原文顺序？改变则必须在 `coverage-map.md` 写出理由；没有充分理由就恢复原顺序。

## 三、教学交付预算与 delivery_role（新增核心约束）

### 3.1 delivery_role 定义

引入与 `practice_mode` 平行的字段 `delivery_role`，用于区分题目的课堂优先级和呈现方式：

| 值 | 含义 | 学生版默认呈现 | 是否计入本节课堂预算 |
|---|---|---|---|
| `core` | 本节必须完成的入口、关键证明、方法示范或边界反例 | 题目和必要书写空间 | 是 |
| `support` | 为完成 `core` 提供的短微知识、已解例或即时反馈 | 紧邻核心题，不能另起一轮活动 | 只计阅读时间 |
| `self-study` | 同方法的换数据练习、重复变式或拓展 | 题库/附录，可课后完成 | 否 |
| `reference` | 教师证明细节、易错分析、评分依据 | 隐藏在教师版 | 否，但计入教师备课量 |

**注意**: `guided/unprompted` 继续只描述提示规则，不能再被用来表示课堂优先级。一个 `guided` 题可以是 `self-study`，一个 `unprompted` 题也可以是 `core`。

### 3.2 课堂预算配置

在配置中增加以下字段（通常在启动前通过 `prompt_dialog.py` 收集）：

```yaml
delivery_profile: classroom       # classroom / self_study
lesson_minutes: 90
opening_minutes: 5
closing_minutes: 5
buffer_minutes: 5
core_task_limit: 12                # 超过即要求合并或拆课
max_student_pages: 6               # 仅作警告，不用缩小字体解决
```

生成前先建立 `lesson-budget.md` 或等价 JSON，至少列出：`qid、delivery_role、practice_mode、预计学生动作分钟、教师核对分钟、support 阅读分钟、前置依赖、carrier_qid`。硬门槛是

`opening + closing + buffer + Σ(core 学生动作与核对时间 + 课堂内 support 阅读时间) <= lesson_minutes`。

若不满足，流程必须在 TeX 写作前返回 `OVER_BUDGET`，依次尝试"合并同一主要动作的题 → 将重复变式移到 `self-study` → 缩短为一个共享示范 → 建议拆成下一课"；不得靠两栏、缩小字号或要求教师现场跳题来掩盖超支。若核心证明和三类未定式都无法在预算内闭合，输出"建议拆课"的分课方案，而不是继续生成一节过载的讲义。

### 3.3 题组压缩原则

- **每个方法族只保留一个课堂载体题**：先选能暴露方法必要性的示范，再选一个确实改变判断的反例或迁移；同法换数据题进入 `self-study`。
- **支持节点复用**：一个载体题可以在 `coverage-map.md` 中承接多个原文节点。新增 `carrier_qid`、`reuse_group`、`must_preserve` 和 `omission_reason`，允许"节点保留、独立题删除"。
- **证明唯一性**：证明只保留一条完整论证链。策略段、分步填空、教师备注不能重复同一证明；后续题只检验一个尚未完成的动作。
- **knowledgebox 汇总机制**：汇总已经建立的公式和适用边界；不得为了每个公式再生成一题。微知识卡解决当前前置即可，不把教材段落逐句改造成问题。
- **核心题时间约束**：课堂核心题的预计时间必须包括学生写作和一次核对；`unprompted` 题不能再默认"全班等待直到完成"。

### 3.4 coverage-map.md 扩展字段

在覆盖表每行记录中增加以下字段：

`原文节点 | 学案位置 | 学习目标 | 对应问题/材料 | delivery_role | practice_mode | carrier_qid | planned_minutes | 是否同知识点首题 | 预计时间 | 推荐讲法 | 易错点 | 来源 | 删改理由`

其中：
- `delivery_role`: `core` / `support` / `self-study` / `reference`
- `carrier_qid`: 若此题承载多个原文节点，填写主载体题号；否则为空
- `planned_minutes`: 学生预期完成时间（含首次核对）
- 其他字段保持原有含义

## 三、题目状态 practice_mode（判定规则权威文本）

每道题在台账与源文件中带有统一状态字段 `practice_mode`（写作者执行口径见 `prompts/subagent_prompt.md` 第 9 条）：

- **guided（常规引导题，缺省值）**：允许题前材料、微型知识点、提示行或分步提示；用于首次引入知识点、关键转折和综合题。
- **unprompted（无提示纯习题）**：学生版只呈现自洽题干和书写空间，不添加研究目的、解题方向、提示、步骤性小问或暗示性过渡；教师版仍保留完整参考解答、唯一推荐讲法、易错点和评分点。

**unprompted 不是省略必要定义的快捷方式**：题干所需对象、运算、记号和条件必须已经在此前材料或示范题中明确给出。若题目引入新知识、改变主要方法或存在依赖缺口，必须恢复为 guided，并补充最小前置说明。

选题与定组时，按以下规则确定 `practice_mode`，不凭题号、篇幅或课堂时间调整：

1. 同一知识点先保留至少 1 道 guided 示范题，确保入口、关键转折和书写规范已经示范。
2. 同一知识点的后续题目只有在主要动作、所用定义和解法骨架与示范题相同，且仅更换数据、对象或表述时，才标为 unprompted。
3. 只要新增关键转折、反例边界、证明负担、表示法或迁移对象，就标为 guided；只有题干自足且满足第 2 条时才可标为 unprompted。
4. 每个知识点保留至少 1 道 guided 示范题；其余题目逐题按上述条件判定，不能因题量或时间改变状态，也不能用 unprompted 隐藏题量问题。

## 四、 多智能体并发处理流程（Multi-Agent Pipeline）

当教材材料较长（如整章教材）时，按以下固定流程切片；材料较短时也执行相同顺序。

### 步骤 0：创建或核验 self 独立输出目录
检查目标目录下是否存在 `self` 文件夹：
- 若无 `self` 文件夹，自动新建 `<target_dir>/self`；
- 若已有 `self` 文件夹（且非空），或目标输出文件发生重名冲突，**严禁静默覆盖**，必须调用 `ask_question` 工具向用户询问并确认处理方案（如覆盖、另存或备份），征得用户同意后再继续；
- 随后将脚手架模板（`main.tex`、`header.tex`、`footer.tex`、`config.yaml`、`student.tex`、`teacher.tex` 等）及各小节切片 `sec*.tex` 统一生成置于该 `self/` 目录下。

### 步骤 1：全书章节锚点定位与知识图谱
使用 `grep_search` 或文件快照提取各小节的起始行号（例如识别 `## § 2.1`、`## § 2.2` 等）。

主 Agent 必须先建立原文骨架表、依赖表和覆盖表，并把它们作为子 Agent 的只读上下文。不能直接把原文按文件或页面切片后并行改写。

### 步骤 2：冻结材料需求并派发研究核验 Agent（默认启用）
- **生成 `research-brief.md`**：主 Agent 从 `coverage-map.md` 与 `dependency-map.md` 冻结材料需求，每行一个需求，字段固定为：`需求ID | 知识点ID/原文节点 | 材料类型(entry/counterexample/history) | 要改变的判断或暴露的边界 | 学生已知前置 | 允许的新对象/记号 | 计划落点 | 必须避免的误解 | 材料来源类型`。每个需求只能有一个主要教学功能，功能说明须落到可观察的前后差异（学生原先的判断、触发修正的数据、修正后判断的使用位置）；无明确教学需求者标记 `NO-NEED`，不新增材料。`材料来源类型` 三选一：`REUSE-ORIGINAL`（复用原文，保留锚点与复核结果）、`SELF-CONTAINED`（自构数学例子，凭完整定义与计算核验并标为自构）、`EXTERNAL`（历史/经验事实，需外部文献或可靠本地摘录）。长度预算（卡片数、字数、题目上限）先于检索数量写入本文件，预算表与卡片字段见 `prompts/research_prompt.md`。
- **派发研究核验 Agent**：研究 Agent 只接收 `research-brief.md`、相关原文片段与三张映射表只读摘录，按 `prompts/research_prompt.md` 输出 `research-cards.md` 与 `research-gaps.md`；每个需求最多 2 张候选卡片，无可靠来源或无法复算时输出 `REJECTED`，不得用常识补写来源。研究 Agent 不写 `sec*.tex`、不改变章节顺序、不自行决定材料是否进入正文。
- **主 Agent 两道闸门核验**：来源闸门（核对 URL/书目、人名、年代、定理表述与引用范围，不可定位原文者标 `unverified`，不得进入正文）与数学/教学闸门（独立重算，检查定义域、量词、边界值、对象类型与前置闭合）。通过者标 `approved` 并把卡片 ID、落点、功能与核验结论登记到 `coverage-map.md`。
- **生成材料包**：主 Agent 为每个切片生成 `material-pack-secN.md`，只含已批准卡片、使用顺序、不得泄露的结论、最小前置定义与桥接句要求；不得把整份研究文件原样塞入切片 prompt。材料包定稿后用 `python scripts/evidence.py materials-index <project> --out <project>/.pd/materials.json` 生成机器索引（字段与口径见 `prompts/research_prompt.md`）。
- **跳过条件**：已有可靠材料且 `coverage-map.md` 的引例/反例功能均已覆盖时可跳过研究 Agent，跳过理由记入 `research-brief.md`。**跳过检索不等于跳过批准与回溯**：复用或自构的材料仍须登记来源类型、保留可定位锚点与复核结果，并由主 Agent 生成批准材料包。
- **状态词表（字段归属与取值，全包统一）**：

  | 字段 | 允许取值 | 谁能设置 / 转换 |
  |---|---|---|
  | 需求状态（research-brief 行） | `NO-NEED` / `ACCEPT` / `REJECT` / `NEED-PREREQUISITE` | 主 Agent 冻结需求；研究 Agent 只给出后三者之一作为初核建议 |
  | 卡片状态（research-cards） | 候选 / `REJECTED` / `unverified` / `approved` / `rejected` | 研究 Agent 只产出候选或 `REJECTED`；`approved/rejected/unverified` 只能由主 Agent 两道闸门转换；研究侧的 `ACCEPT` 不等于 `approved` |
  | 验收结论 | `PASS` / `REVISE` / `NEEDS_EVIDENCE` | 独立验收 Agent 出具并绑定所审版本；主 Agent 汇总 |
  | 任务运行状态 | `planned/ready/running/produced/checked/accepted/blocked/failed/stale` | `pdstate.py` 与主 Agent 维护（见步骤 3.5） |

### 步骤 3：派发切片任务（强制：一节一子 Agent；开篇专员经职责判定后派遣）
- **必须为每个 Section（小节）派遣一个独立的子 Agent**（强制要求，严禁主 Agent 集中单体生成所有小节，亦严禁合并多个小节交由同一个子 Agent 处理）。宿主调度保留“一节一写作者”的逻辑边界和低成本目标；实际模型名由宿主已配置的映射提供，不硬编码一个宿主不存在的接口。并发度由可用槽位和任务依赖决定；失败返修按 attempt 串行处理，不为润色额外派多个写作者。题目或标题的局部修订只处理受影响范围。
- **开篇职责判定与开篇子 Agent**：派发切片前先判定开篇职责归属。若原材料已有完整的章首引例，或第一节本身已承担开篇功能，允许合并教学职责——开篇与首节分工使用该例，或让 `sec0` 只保留极短的必要背景；不得仅因存在 `sec0` 机制就强制增加一段重复内容。判定为需要独立开篇时，额外派遣一个专属子 Agent（“开篇引例与历史引入专员”，同一低成本档位）撰写 `sec0.tex`：**以叙述为主，较少使用问题**——以 discussion/exposition 段落为主体，至多穿插少量进入题，不得改造成完整题链；每个引例、反例与历史事实都必须可回溯到核实记录，严禁自行编造来源或史实；原文提到某人某事，不授权补出更具体的年代、因果或归属。
- **入口约定先行**：需要独立开篇时，开篇专员先提交一份简短的“开篇—首节入口约定”草案，主 Agent 核定后冻结（记录于 `material-pack-sec0.md` 或章节总览，不另造台账）：学生此时已知什么、能执行什么动作；开篇建立哪个观察、留下哪个未解问题；各结论的信息首次揭示位置；首节如何使用开篇产物、重访同例时增加什么新动作。开篇专员据冻结版本写作，首节切片共用同一份约定；开篇与首节完成后联合提交独立教学验收（步骤 4.5）。字段详见 `prompts/subagent_prompt.md` 开篇模板。
- 先完成三张基石映射表（`source-map.md`、`dependency-map.md`、`coverage-map.md`）与步骤 2 的研究核验，再按小节逐一派发切片任务。每个小节切片必须由专属的子 Agent 独立撰写对应的 `sec*.tex`。切片 Agent 固定使用低成本档位以控制成本；主 Agent 与切片 Agent 使用相同的输入约束、输出格式和验收标准。切片 Agent 只能使用对应 `material-pack-secN.md` 中状态为 `approved` 的卡片；材料包不足时返回缺口清单和所需字段，由主 Agent 补齐后重新派发，切片执行者不得自行检索或编造来源。
- **派发参数配置示例**（字段名由宿主适配层映射到实际调用接口；逻辑任务使用低成本档位，不得自动回退到更贵模型；并发数、超时与有限重试属部署配置）：
  ```json
  {
    "Subagents": [
      {
        "TypeName": "self",
        "Role": "第1节切片制作专员",
        "Model": "<由宿主已配置映射提供的低成本模型名>",
        "Prompt": "<依照 prompts/subagent_prompt.md 填入>"
      }
    ]
  }
  ```
- **派发前确定性检查**（不花一次子 Agent 调用来发现输入未就绪）：原文范围可读、材料包已批准或明确为空包、占位符全部替换、跨节接口已冻结；任一不满足，先修任务包再派发。
- **最小上下文**：派发时只带本节任务包（清单见 `prompts/subagent_prompt.md`），不附整份工作流与课堂操作指南；切片写作者凭本节任务包完成任务，无需读完整生产状态机。
- **Subagent Prompt 黄金模板**：集中维护于 `prompts/subagent_prompt.md`，复制后替换 `{{INPUT_FILE}}`、`{{START_LINE}}`、`{{END_LINE}}`、`{{SECTION_TITLE}}`、`{{OUTPUT_FILE}}` 等占位符即可，避免硬编码路径散落各处。开篇子 Agent 使用同一文件中的“开篇引例子 Agent 模板”。候选输出均写入 `pdstate.py start` 创建的独占 attempt 目录（如 `self/.pd/candidates/sec0/attempt-0001/sec0.tex` + `result.json`，校验后提升为 `self/sec0.tex`）。研究核验 Agent 模板见 `prompts/research_prompt.md`。

### 步骤 3.4：对话层派发补充（启用对话层时必须执行；关闭时不加载本节详细协议）

对话化工作服从“一节一子 Agent”边界：由负责该 section 的子 Agent 完成，主 Agent 负责跨 section 的冲突解决、版本一致性与最终验收；不得为同一 section 再拆出多个并行写作者，也不得让子 Agent 自行改动全局表格、章节顺序或配置。

- **派遣前冻结**：主 Agent 必须先冻结该 section 的三张映射表记录、`overview-guide.md` 的对话蓝图（核心冲突、入口引例的可观察对象/最小计算/未决问题、悬而未决句、信息首次揭示位置）、相关 qid 与 `practice_mode`、以及本节的对话配置（是否启用、最大回合数、学生版揭示策略）。派发提示使用 `prompts/subagent_prompt.md` 的「对话增强模式」固定字段，只给出“先读哪些文件、只改哪里、如何返回结果”的顺序，不替子 Agent 写出台词结论。
- **子 Agent 四阶段产物**：`dialogue-brief`（冲突、角色、未决问题、承接 qid）→ `dialogue-script`（逐句台词、角色动作、信息揭示位置）→ 候选切片 TeX（保持 qid、题号与环境闭合）→ `dialogue-check`（PASS/REVISE 及证据行号）。跨 section 矛盾标记 `CROSS-SECTION-BLOCKER` 交主 Agent。
- **主 Agent 汇总顺序**：先审 dialogue-brief（冲突确实来自原文、证据可复核、承接 qid 存在），再审 dialogue-script（角色各有数学动作、遵守回合上限、未提前泄露答案），通过后才接受 TeX 补丁；一次只合并一个 section，记录变更到 `coverage-map.md`；然后做跨节一致性审查（术语首次定义、反例分类、主线与下一节接口），最后运行 `check_dialogue.py` 等结构检查与编译。
- **失败与重派**：数学冲突以原文和独立重算为准，不允许“折中台词”；学生版泄露标 `dialogue-answer-leak`，只重写对白，实质提示无法移除时该题改 guided 并更新覆盖表；对白孤立标 `dialogue-orphan`，优先删除或改接真实 qid，不得添加装饰性题目；依赖缺口标 `dialogue-dependency-gap`，先补最小 microknowledge；重复动机标 `dialogue-redundancy`，删重复句；连续两次格式修复失败时主 Agent 收回补丁用最小模板实现；子 Agent 越界改动全局文件时整批拒收并缩小派发范围重派。
- **并发约束**：不同 section 的对话化子 Agent 可并行，但首次确定角色表/宏接口/揭示策略、修改共享模板或配置、跨节定义前置、任何失败修复与重派、最终合并与交付，必须串行。每节不超过一名写作子 Agent 加一名独立验收 Agent，不为“润色台词”额外调用。
- **独立验收**：验收 Agent 只接收改造后的 section、题链摘要、原始 solution、`dialogue-brief` 的格式化接口与验收标准，按 `dialogue-answer-leak / orphan / dependency-gap / redundancy` 分类返回 PASS / REVISE / NEEDS_EVIDENCE；`NEEDS_EVIDENCE` 不当作通过。
- **协作记录**：在 `research-brief.md` 或新增 `dialogue-log.md` 记录每次派遣的 section、输入版本、子 Agent 输出状态、退回原因、重派次数与最终验收结果；该记录不进入学生版或教师版正文。

### 步骤 3.5：运行契约与候选提交（scripts/pdstate.py）

每次运行由主 Agent 执行 `python scripts/pdstate.py <project> init` 建立 `.pd/run.json`：`schema_version`、`run_id`、切片顺序、源文件/模板/配置摘要（SHA256）与任务表。逻辑任务 ID 统一为不带扩展名的 `sec1` 等，输出文件名单独记为 `sec1.tex`。

- **任务标识**：`run_id / task_id（=section_id）/ attempt_id / input_digest`（任务输入摘要）。
- **状态机**：`planned → ready → running → produced → checked → accepted`，另有 `blocked / failed / stale`；这些是运行状态，不是教学质量等级。转换受限：输入包就绪 `planned → ready`；`ready → running` 只能由 `start` 新建 attempt；`running → produced` 只能由 `submit`；`produced → checked → accepted` 由主 Agent 在自查/验收完成后 `mark`；当前输入改变使 `ready/running/produced/checked/accepted → stale`（由 `invalidate` 设置）；`stale/failed/blocked` 修好输入后 `mark ready` 重试。stale 不能直接 submit 或 mark accepted。
- **派发（start）**：派发前执行 `python scripts/pdstate.py <project> start <task> [--input <文件或目录> ...] [--prompt-file <提示词>]`，把本次实际发送的材料（提示词、原文片段、该节映射摘录、材料包、跨节接口、对话蓝图、配置与 TeX 宏接口）交给 start；脚本创建独占目录 `.pd/candidates/<task_id>/attempt-NNNN/`，将输入快照存入 `inputs/`（之后不原地重写），并冻结 `task.json`（schema_version、run_id、task_id、attempt_id、input_digest、allowed_output）。
- **候选提交（submit）**：子 Agent 把结果写入自己独占的 attempt 目录：`secN.tex` 与 `result.json`（result 必须复述 run_id/task_id/attempt_id/input_digest 四身份字段并给出输出文件 SHA256）；主 Agent 用 `pdstate.py submit <task>` 依次校验：run/task/attempt 与当前派发一致 → 任务处于 running → 冻结输入与当前任务输入一致 → result 输出路径与哈希正确 → 候选非空且结构通过，全部通过才原子提升为正式切片。任一失败不触碰正式切片。新 attempt 编号递增、不覆盖旧 attempt；旧候选与迟到结果不得覆盖新版本。
- **恢复**：同一运行恢复时读取 `run.json`，只重跑未完成或已失效（stale）任务；输入摘要变化的旧结果进入 `stale`，不得继续作为当前版本的通过证据。`invalidate` 只更新 run.json 中的最新摘要，不覆写旧 attempt 的冻结摘要；无输入变化时重复 invalidate 幂等。
- **单写者**：批准材料包、`main.tex` 骨架、全局台账与 `run.json` 由主 Agent 单写者维护。
- **成本记录**：宿主提供实际 usage 时用 `pdstate.py record` 记录每任务输入/输出 token、重试次数与实际模型路由；无法取得时留空（null/unknown），不填写估算调用量，不编造节省百分比。

### 步骤 4：装配
切片执行者只依据已确定的节点表起草学习单元，不得自行决定跨单元的概念顺序、补充高级概念或删除原文结论。各切片完成后，逐项通过顺序、依赖和覆盖审校，再由 `main.tex` 按文件顺序装配（先 `\input{sec0.tex}` 开篇切片，再依次装配各 `sec*.tex`）；装配不替代内容审校。

### 步骤 4.5：独立教学验收（默认启用）
装配前后各有一次验收触发点，验收规范、两阶段输入边界与证据格式见 `prompts/acceptance_prompt.md`：

- **调度屏障**：原型验收通过前，对开篇/首节入口有依赖的小节不进入完整写作（可准备任务包）；原型通过后按任务依赖并行派发，局部缺口只阻塞受影响任务。跨节接口（输入概念、学生已可见结论、输出结论、首次揭示位置）变更后，按依赖图标记受影响切片与验收记录失效，无需全文重写。
- **原型验收**：开篇切片与首个实质任务（首节原型）完成后，先运行一次独立教学验收，避免整章完成后才发现入口职责错误；原型验收记录属调度阶段记录，仅放行后续写作，不替代最终 chapter 验收。
- **装配后验收**：全部切片装配后，检查跨节接口、答案首次揭示位置与实例重访带来的新问题；未改变的内容不必全文重审。

### 步骤 5：材料回溯、编译、诊断与版本快照
运行构建脚本前，主 Agent 对每个已写入材料执行回溯检查：正文中的材料 → 卡片 ID → `research-brief.md` 需求 → `coverage-map.md` 功能记录 → 来源摘录；任一环节断链即退回切片。**编译通过不代表材料验收通过；脚本（编号、泄露扫描、计数核对）通过也不代表教学验收通过**——确定性检查与步骤 4.5 的学生视角审读并列执行、互不替代，不得把来源表填满视为内容真实，也不得把关键词扫描视为教学合格。`compare_versions.py` 报告“答案疑似项待复核”时须人工复核（`.pd/review-notes.md` + `.pd/review-notes.json`，格式见 `prompts/acceptance_prompt.md`）后再交付。

随后按以下顺序运行构建脚本（所有脚本以显式项目路径调用，以下为项目根目录视角）：
```bash
python scripts/check_numbering.py self/          # 装配完整性 + 题链结构 + 逐题身份与答案关联
python scripts/check_dialogue.py self/           # 对话层结构与泄露（未启用对话层时自动放行）
python scripts/build.py self/                    # XeLaTeX 双遍编译 + 日志告警验收 + 双版 SUMMARY 核对
python scripts/compare_versions.py self/         # 学生版泄露扫描（含答案源级检查）+ 双版诊断
python scripts/deliver.py self/                  # 交付汇总门禁（见步骤 5.5）
```
**运行环境要求**（集中在首次运行前预检，`python scripts/build.py self/ --check-env`）：Python 3.10+、XeLaTeX（TeX Live / MiKTeX）、中文字体、`exam-zh-choices` 宏包、poppler 的 `pdftotext`。

注意：`build.py` 每遍编译均检查返回码并设超时（`--timeout`，默认 300 秒；超时属执行故障可重试，确定性 TeX 错误不重试）；`config.yaml` 更新后自动重新生成配置。出现未定义引用、严重 Overfull（默认 >10pt）、mdframed bad break、multicol 栏数被自动改变、`Package problem-driven Warning` 或双版 SUMMARY 计数不一致时判为失败；编译返回码为 0 不等于验收通过。学生版 Underfull 留白默认只诊断不判失败，
阈值可用 `--max-overfull-pt`、`--max-underfull-teacher` 等选项调整。`compare_versions.py` 在证据缺失（缺日志 SUMMARY）时返回 2（无法完成检查），不得以“证据缺失”冒充“检查通过”；独立诊断用途加 `--diagnostic`。检查脚本均支持 `--json` 输出 schema_version 2 结构化结果（status/scope/input_digest/pdf_sha256/issues/evidence/tool_version），供交付汇总使用。

### 步骤 5.5：交付汇总门禁（scripts/deliver.py）

技术检查与教学验收互不替代；交付前由 `deliver.py` 汇总全部证据（schema_version 2 门禁），**全部满足**才通过。旧版 Markdown/JSON 证据可保留为历史，但缺少字段时必须重建/复验，不自动补摘要、不把历史 PASS 转成当前 PASS。

- **正常模式顺序**：确定性生成配置（gen_config）→ check_numbering → check_dialogue → build → compare，然后核对验收；报告只信本次调用产出的新文件（调用前删除旧报告，子进程异常或非零退出即停止放行，不回读遗留旧 pass）。
- **`--skip-checks` 语义**：复用已完成的检查，但仍逐项验证工具/schema 版本、报告 input_digest 与当前输入摘要一致、绑定的 PDF 哈希与实际产物一致、记录的日志/PDF 文本证据哈希与实际文件一致；跳过执行不等于跳过验证，不再使用 mtime 作为通过依据。
- **放行门槛**：编号、对话、构建必须 pass；compare 可以是 pass，或是所有疑似项都有当前有效处置记录的 review（经 `.pd/review-notes.json` 哈希绑定核对）；不得把所有脚本的 review 一概视为通过。
- **教学验收**：`run.json` 的 `required_acceptance_scopes` 声明的必需 scope 不得缺失，每个必需 scope 的 `.pd/acceptance/<scope>.json` 必须为 PASS、绑定当前摘要与学生版 PDF 哈希、reviewed_qids 覆盖全部必需 qid；open 问题禁止 PASS。技术证据齐备但教学验收未完成时返回“待验收”，保留已生成的审读草稿（`.pd/review/`）。
- **材料批准链**：正文有 `% card:` 引用时必须有 `.pd/materials.json` 且五核对通过（卡片存在且 approved → requirement 在 research-brief → 材料包批准记录 → 证据定位 → coverage 实际 qid）。
- **原子发布**：发布前重新核对输入与 PDF 哈希；先写临时目录（双版 PDF + manifest.json），全部成功后再原子切换到 `release/`；失败时保留上一版完整 release，不出现新旧 PDF 混合发布。manifest 记录有序切片、输入摘要、PDF 哈希、所有检查与验收证据哈希、实际工具版本。

诊断措辞统一为“未发现已检查范围内的泄露标记”；不得由文件存在或退出码 0 推断整个工作流已完成。

### 步骤 6：回归验证
模板、宏定义或检查脚本改动后，运行 `python scripts/test_templates.py`（基于当前模板构造最小工程的真实编译回归）与 `python scripts/test_runtime.py`（F05–F08 证据链的 16 项运行时回归，临时目录、不触碰真实工程）。`examples/eg.tex` 系列与 `scripts/test_examples.sh` 仅作旧示例参考，不再充当模板回归证据。

## 五、 对话层协议（可选；`dialogue_enabled: false` 时无需加载本节）

对话层在现有生产协议上增加一种受控的叙事承载：将每个启用 section 开头的背景/动机段改造为短课堂片段（`sectiondialogue`），把首个入口题（通常是 Entry 题或首个 guided 题）的题干前置为“提问—猜测—检验—暂时结论”的引例对话（`exampledialogue`）。默认风格接近课堂讨论：角色提出异议并推动修正，台词简洁、数学动作明确，不写成戏剧对白或无关闲聊。**对话只改变叙事承载，不替代数学任务、证明链、题号与 qid**；`dialogue_enabled: false` 时完全沿用旧流程，未启用对话的旧 section 行为完全不变。TeX 环境与配置字段见 `references/tex-interface.md`。

**对话脚本卡**（写 TeX 之前逐节填写，字段并入 `overview-guide.md` 的「对话蓝图」）：

| 字段 | 要求 |
|---|---|
| 冲突 | 来自原材料的猜想、反例、计算差异或定义歧义 |
| 角色 | 教师固定为 $\Psi$（组织），学生固定为希腊字母：$\alpha$（严格性）、$\gamma$（反例）、$\beta$（算例）；按需 $\delta$（过早确信）、$\kappa$（无穷回退或定义膨胀）、$\omega$/$\theta$（替代证明与方法论）。台词写作 `\speaker{$\Psi$}{...}` 形式，严禁使用 Teacher/Alpha 等英文角色名 |
| 回合 | 观察 → 猜测 → 质疑/反例 → 暂时结论 → 下一任务 |
| 数学证据 | 至少一个可复核的数值、图形、等式或定义条件 |
| 未决问题 | 必须由后续题目或 exposition 回答 |
| 信息边界 | 学生版不得提前出现本节证明结论 |

**section 开头写作规则**：先从具体对象或反常数据开始，再说本节数学任务，禁止一上来罗列定义和定理；至少出现一次“看似合理但需要检验”的猜想或一个能改变直觉的反例；$\Psi$（教师）末句给出下一步任务但不宣布证明结果；原有 exposition 中不可替代的历史、术语、范围说明保留在对话之后，重复的动机句删去并在覆盖表登记；开头对话必须与下一题的第一个真实动作相接。

**引例对话写作规则**：入口题保留原 `qid`、`qtype` 与答案结构，只在 `\begin{probchain}` 之前增加 `exampledialogue` 并以注释 `% dialogue: qid=<入口题qid>` 绑定（enumerate 内首个 `\item` 之前不允许出现盒子环境）。对话必须完成四件事：①指出对象和可直接观察的事实；②一个角色提出可能错误或不完整的猜测；③另一角色要求计算、分类或反例；④以一个尚未完成的动作结束，随后由题目承担该动作。不得在对话中出现 `solution` 的完整推导、教师唯一推荐方法或后续定理名称；入口题本身是证明题时，只揭示证明目标和关键障碍，不揭示引理顺序。

**与已有内容块的接口**：

- `microknowledge`：对话只能使用此前已定义的对象；引例需要新符号时先按现有规则插入最小定义。
- `proofstrategy`：对话可出现“需要找到一个不变量/计数方法”等方向性语言，但不得泄露结论；完整策略仍放在证明题前。
- `teacherNote`：记录每句对白的教学功能、预期误区和揭示时机；角色心理分析不写入正文。
- `knowledgebox`：节末总结对话中哪些猜测被证实、修正或放弃，并连接下一节。
- `practice_mode`：对话不是提示的豁免通道。unprompted 题前不得配置 `exampledialogue`（`check_dialogue.py` 硬检查）；对白若提供实质步骤，题目必须标为 `guided` 并更新台账。
- 单源双输出：对话源只保留一份。台词一律 `\speaker{角色}{台词}`，每句一个主动作，角色通常 3–4 人；会泄露答案的句子必须放入 `\dlgteacher{...}`（教师版专属，学生版默认隐藏，`dialogue_student_reveal: full` 时全显）；对话块内禁止 `solution`/`teacherNote`/`\fillin`/`\ansspace`。禁止分别手工改写学生版和教师版。

**对话层的结构与泄露检查**由 `scripts/check_dialogue.py` 执行（硬门槛，只验证结构与泄露，不以台词字面相似度判定质量）：每个启用 section 有且仅有一个 `sectiondialogue` 且位于 `\section*` 之后、首个实质题/定义之前；每个入口 qid 有绑定的 `exampledialogue`；绑定 qid 与题目 qid 一致且全章不重复；对话块内无答案性内容；每个对话块在 `coverage-map.md` 有承接记录（`dialogue-hook` 行）；台词句数不超上限。错误类型：`dialogue-answer-leak`、`dialogue-orphan`（对白无后续数学任务承接）、`dialogue-dependency-gap`、`dialogue-redundancy`（处置方式见 `templates/error-log.md`）。

## 六、 质量验收清单 (Checklist)

### 逻辑验收（先于排版验收）

- [ ] 每个定义、记号、例题、命题和证明都能回溯到原文锚点，且学案顺序没有无理由前置。
- [ ] 每道题的对象、运算、记号、维数条件和所用结论均已提供或明确属于已知前置。
- [ ] 每个学习单元都存在“材料/定义—示例—问题—反馈—下一节点”闭环。
- [ ] 原文核心论证链没有被形式化题、迁移题或反例题替代；证明步骤都能由前面已建立的事实推出。
- [ ] 未为了满足固定题型而添加与原文主线无关的内容。
- [ ] **开篇职责与入口约定**：是否先判定开篇职责归属（原材料已有完整章首引例或首节已承担开篇功能时，合并职责或只保留极短必要背景，未强制重复一段内容）？独立开篇时是否先冻结“开篇—首节入口约定”（学生能做什么、建立哪个观察、留下哪个未解问题、各结论的信息首次揭示位置、首节接续的新动作），开篇与首节共用同一约定？该切片是否以叙述为主、较少使用问题，且全部素材可回溯到核实记录？
- [ ] **揭示顺序**：原材料用 `\pause` 等手段延迟揭示的节点，静态输出是否保留先判断、后反馈的次序？首个实质任务要学生自己得出的答案是否未被开篇或背景段提前公布？
- [ ] `overview-guide.md` 的主线、依赖和转折与实际题目顺序一致，而不是生成后的事后解释。
- [ ] 学生仅凭当前材料能完成抽样题；卡住的位置必须补材料或拆题，仍无法闭合的题目删除。

- [ ] **问题驱动性**：是否做到了“先有探究体验，再给形式定义”？
- [ ] **题链整体性**：各题目是否杜绝孤立罗列？题间过渡是否只在产生新联系时书写（自然融入题干），而不是按“每题 1~2 句”机械补写？
- [ ] **unprompted 独立性**：每个 unprompted 题均可凭此前材料独立作答，且 `coverage-map.md` 台账指向一个已完成的示范题号或知识点 ID；未把同一知识点的整组题全部设为 unprompted。
- [ ] **unprompted 双版一致性**：unprompted 题的学生版不出现提示性标签、提示词或教师备注；教师版题目正文与学生版逐题一致且有解答。（脚本只能检查 `\practicemode` 取值与 unprompted 题块内的提示标记，题干自足性与台账指向须人工核验。）
- [ ] **知识自足与前置定义**：是否严格确保题目中所用知识是已知的？遇到新对象、新运算或新记号时，是否已在题干前/中补充了必要的定义与讲解，杜绝了未经定义便直接出题？
- [ ] **文风严谨度**：全篇文风是否简明、严肃、克制？是否杜绝口语化、网络梗或夸张修辞？是否避免引入过多无关的额外复杂概念？
- [ ] **列表规范性**：多条知识点、性质陈列是否规范使用了 `enumerate` 环境分条展示？
- [ ] **命名规范**：`main_title` 已经用户确认（默认「学案」，未自行杜撰）；各小节 `\section*` 标题均以大写罗马数字（I、II、III……）开头且按装配顺序连续递增。
- [ ] **题号连续性**：学生版与教师版各题编号完全一致，全章无重复断号。
- [ ] **逐题身份与答案关联**：每道题有全章唯一 qid；每题恰好一个 solution 与一个 teacherNote；切片无计数器重置或版本开关宏（check_numbering.py 硬检查）。
- [ ] **节末结论框与证明支架**：每节末有 knowledgebox 总结本节结论；证明支架按方法新颖程度配置，策略段和分步题干不重复交代同一完整证明路线，不泄露待填答案。
- [ ] **对话层（启用时）**：每个启用 section 的开头对话有可追溯的数学冲突和未决问题；每个入口引例由对白自然引出且题干仍是学生完成任务所需的最小充分信息；对话中的反例明确说明破坏了哪个猜想/条件，不把局部反例误写成主命题反例；学生版只看到观察、猜测和问题，泄露句全部位于 `\dlgteacher` 内；对白促进后续数学动作而非增加篇幅或装饰性戏剧；`check_dialogue.py` 通过，每个对话块在 `coverage-map.md` 有 `dialogue-hook` 承接记录；未启用对话的旧 section 行为完全不变。
- [ ] **留白与版面**：学生版书写留白充足；教师版紧凑且无多余大片空白。
- [ ] **版本干净度**：学生版 PDF 中未泄露教师专属标记（【解】【证明】、参考解答、教学要点、评分等，由剥离机制与 compare_versions.py 检查）与教师备注，且不显示题型标签【xx题】。题干中合法的“试证明”等教学用语不属于泄露，验收时结合任务判断，不误判违规。
- [ ] **子 Agent 边界校验**：是否严格为每个 section 独立派遣了一个专属子 Agent（一节一子 Agent，严禁主 Agent 代写或合并小节）？开篇是否先经职责判定再决定是否派遣开篇专员？是否按默认配置派遣了研究核验 Agent（或已在 `research-brief.md` 记录跳过理由与批准路径）？切片子 Agent 是否只使用主 Agent 冻结的主线、依赖表、覆盖表和批准材料包，且没有自行改变章节顺序、自行检索或添加无来源材料？
- [ ] **独立教学验收**：是否由未参与规划写作、使用新上下文的验收 Agent 按两阶段边界（先学生可见内容，后教学与来源核对）完成验收？验收粒度是否按学习依赖的连贯片段（开篇至少与首个实质任务一起读）？结论是否为 `PASS` / `REVISE` / `NEEDS_EVIDENCE` 之一且绑定所审版本？每条实质问题是否均有“修复并核验”或“给出依据后撤销”的结果？脚本通过未被当作教学验收通过。
- [ ] **材料回溯**：正文中每个引例/反例/历史材料可沿“正文 → 卡片 ID → `research-brief.md` 需求 → `coverage-map.md` 登记 → 来源摘录”完整回溯，无断链；编译通过不视为材料验收通过。
- [ ] **来源闸门**：每个进入正文的材料均按来源类型留有可复核证据：`REUSE-ORIGINAL` 有原文锚点与复核结果，`SELF-CONTAINED` 有完整定义与复算过程并明确标为自构，`EXTERNAL` 有可复核的 URL/书目与摘录或页码；历史事实不超出原文授权的具体程度（不补出原文没有的年代、因果或归属），不只依赖搜索摘要；`unverified` 材料未进入正文。
- [ ] **数学复算**：主 Agent 已独立重算每个例子和反例（定义域、量词、边界值、对象类型、前置闭合）；反例只改变一个可识别条件并写明保留/破坏的性质。
- [ ] **功能唯一**：每张材料卡片承担且仅承担一个主要教学功能（改变判断、暴露边界或支撑证明中的至少一项），功能说明落到可观察的前后差异（学生原先的判断、触发修正的数据、修正后判断的使用位置），已登记入覆盖表；重复或装饰性材料已删除。
- [ ] **长度预算**：各落点材料在 `research-brief.md` 的卡片数、字数与题目上限内（sec0 主口径为核心叙述约 450 个汉字、不含公式字母，页数只作装配粗检；至多 1 引例，需要暴露旧方法边界时再加 1 边界例）；材料后紧跟可完成的数学动作；未把后续小节内容提前讲完。
- [ ] **编译零告警**：通过 XeLaTeX 连续两次编译，引用与页脚总页码 (`\pageref{LastPage}`) 均正确呈现；`build.py` 验收通过（无未定义引用、无严重 Overfull、无 mdframed bad break、双版 SUMMARY 一致）。
