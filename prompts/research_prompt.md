# 引例与反例研究及初核 Agent (Research Agent) 派发规范

本模板集中管理“研究与核验 Agent”的派发提示词、材料卡片字段、状态协议与长度预算。研究 Agent 的职责严格限定为检索整理和初步核验：**不直接写 `sec*.tex`，不改变章节顺序，不自行决定材料是否进入正文**。主 Agent 是最终的事实、数学和教学验收者。

---

## 角色与成本约束

- `TypeName`: `"self"`
- `Model`: `<由宿主已配置映射提供的低成本模型名>`（必须显式指定；不硬编码具体型号）
- `Role`: `"引例与反例研究及初核专员"`
- **默认每章一次研究 Agent 调用**；只有来源争议较大或需求数较多时，才拆成两个串行任务（检索 Agent → 核验 Agent）。若拆分，核验 Agent 只能读取检索结果，不能重新扩张检索范围。
- **跳过条件**：若已有可靠材料且 `coverage-map.md` 的引例/反例功能均已覆盖，可跳过研究 Agent；跳过理由必须记入 `research-brief.md`。**跳过检索不等于跳过批准与回溯**：复用原文或自构的材料仍须由主 Agent 登记来源类型、保留可定位锚点与复核结果，并生成批准材料包。

---

### 阶段 A：主 Agent 冻结材料需求（research-brief.md）

#### 两类内容分工

研究协议只处理确有选择和核验成本的素材：

1. **原文定义、定理和证明**（含原文例题的数学内容）直接登记 `source-map.md`，并在 `coverage-map.md` 跟踪计划落点与实际处置；不强迫每项原文命题都成为研究卡，不为其生成研究需求行。
2. **引例（entry）、反例（counterexample）和确需考证的历史材料（history）** 使用 `research-brief.md` 与材料包。`材料类型` 枚举固定为这三值，不得新增 `entry/method`、`theorem`、`example` 等自由枚举；已有材料卡保留原 ID 便于迁移，新增记录不得突破该枚举。

在派发任何研究或写作任务前，主 Agent 从 `coverage-map.md` 与 `dependency-map.md` 生成 `research-brief.md`。每行一个需求，字段固定为：

`需求ID | 知识点ID/原文节点 | 材料类型(entry/counterexample/history) | 要改变的判断或暴露的边界 | 学生已知前置 | 允许的新对象/记号 | 计划落点(sec0 或 secN、题号前后) | 必须避免的误解 | 材料来源类型`

其中“要改变的判断或暴露的边界”须落到可观察的前后差异：学生原先可能采用什么判断、看见哪组数据后会修正它、修正后的判断将在何处使用。`材料来源类型` 三选一，与核验证据对应：

| 取值 | 含义 | 所需核验证据 |
|---|---|---|
| `REUSE-ORIGINAL` | 复用原文已有材料，不新增检索 | 可定位锚点（文件/页/行/定理号），核验记录必须引用该锚点 |
| `SELF-CONTAINED` | 自构数学例子 | 完整定义、数据与主 Agent 独立复算过程；卡片明确标为自构，不附会文献 |
| `EXTERNAL` | 历史、经验或现实应用事实 | 来源（URL/书目）与相应摘录或页码，核验记录必须附上该摘录 |

核验记录按来源类型分别引用上述证据（锚点 / 数据与复算 / 来源与摘录），不得把不同来源类型的证据统一压成"核验通过"四字。

规则：

1. 每个需求只能有一个主要教学功能；**无明确教学需求**者标记 `NO-NEED`，不新增材料、不派发检索。`NO-NEED` 与"已有材料可用"（`REUSE-ORIGINAL`）是两种不同状态，不得混填；二者都要写明具体依据。
2. 主 Agent 同时列出禁用条件：不能引入尚未定义的运算，不能与已有示范例重复，不能靠故事替代数学任务。
3. **输出 CUT_LIST 时同时列出可合并题、可移入自学题库的题和必须保留的证明/反例；没有明确课堂功能的材料不进入正文**。

| 落点 | 材料卡片数上限 | 正文长度预算 | 题目上限 | 选择原则 |
|---|---:|---:|---:|---|
| `sec0` 开篇 | 2 张（1 引例；仅当需暴露旧方法边界时加 1 边界例） | 主口径：核心叙述不超过约 450 个汉字（不含公式字母）；页数只作装配粗检；教师注释另计但不超过 1 页 | 1–2 道进入题 | 只保留能直接导向第一小节任务的材料 |
| 普通 `secN` 小节 | 1 张主材料，必要时加 1 张边界卡 | 约 250 个汉字或 25 行正文 | 材料后最多 1 道题 | 材料必须服务本小节唯一主要动作 |
| 反例专门题 | 1 张反例卡 | 约 120 个汉字 + 最小计算 | 1 道反例题 | 只改变一个条件，立即检验失效性质 |

行数只作为装配后的粗检，最终以汉字数（不含公式字母）与 PDF 页数为准；`solution`、`teacherNote` 中的完整证明不计入学生版材料预算，但不得借教师答案重复讲述同一背景。可删背景（历史叙述、物理背景）与承担教学功能的核心实例叙述分开计量：背景每则不超过 3 句，且不得挤占核心叙述预算；除非背景本身就是学习目标。

## 阶段 B：研究 Agent 检索与初核（派发提示词模板）

```text
你是“引例与反例研究及初核 Agent”，使用宿主已配置映射提供的低成本档位模型。只处理 research-brief.md 中列出的需求。
不得写 sec*.tex，不得改变章节顺序，不得编造来源，不得把未经核验的候选交给写作 Agent。
每个需求最多输出 2 张材料卡片，严格使用规定字段；没有可靠来源或无法复算时输出 REJECTED。
反例必须只改变一个可识别条件，并写出保留/破坏的性质；引例必须对应一个可观察现象和一个明确数学任务。
所有新对象、运算和记号都要列出最小前置；若超出既有前置，标记 NEED-PREREQUISITE。
严格遵守 research-brief.md 的字数、页数、卡片数和公式数预算。
先给出每张卡片的预计字数与功能，再写材料；不要为了展示候选而填满预算。
sec0 默认只推荐 1 个主引例；仅当需要暴露旧方法边界时再推荐 1 个边界例。背景各不超过 3 句。
若候选超过预算，输出 CUT_LIST，按“功能重复、前置过重、不能导向首题、来源较弱”排序建议删除。
完成后输出：research-cards.md、research-gaps.md，以及逐需求的 ACCEPT/REJECT/NEED-PREREQUISITE 状态。
```

### 输入约束（主 Agent 派发时提供）

- 材料需求表：`research-brief.md`（含预算与禁用条件）
- 相关原文片段：{{SOURCE_EXCERPTS}}
- 三张映射表只读摘录：{{MAP_EXCERPTS}}
- 允许的检索范围：{{SEARCH_SCOPE}}

### 材料卡片字段（固定，不得增删）

`卡片ID | 对应需求ID | 一句话材料 | 最小数学数据/构造 | 改变的条件 | 保留的性质 | 被破坏的性质或观察 | 所需前置 | 数学任务 | 推荐落点 | 来源URL/书目信息 | 来源摘录或页码 | 事实核验状态 | 数学核验状态 | 风险/待查 | 预计正文字数 | 预计公式数 | 认知负荷(低/中/高) | 与现有卡片重复点`

### 输出产物

- `research-cards.md`：全部候选材料卡片（含 `REJECTED` 卡片及缺口说明）。
- `research-gaps.md`：逐需求的缺口与“本章不补材料”结论。
- 逐需求状态：`ACCEPT` / `REJECT` / `NEED-PREREQUISITE`。

硬性要求：

1. 核验证据按来源类型区分：`SELF-CONTAINED` 卡片凭完整定义与可复算的计算核验，明确标为自构；`EXTERNAL` 卡片给出来源证据，历史卡不得为凑数勉强附加无关数学实例；`REUSE-ORIGINAL` 卡片给出原文锚点。反例必须明确“只改变哪一个条件”。
2. 历史材料必须区分原始史实、二手叙述和无法确认的传闻；原文提到某人某事，不授权补出更具体的年代、因果或归属，无法核实的断言建议删除。
3. 无法找到可靠来源时输出 `REJECTED` 并说明缺口，**不得用常识补写来源**。
4. 每个需求最多提交 2 个候选，避免素材堆积。

## 阶段 C：主 Agent 两道闸门核验

研究 Agent 的需求级 `ACCEPT` 只是初核建议，不等于进入正文的批准；只有主 Agent 两道闸门通过后的 `approved` 卡片才可进入材料包（状态词表见 `../references/production.md`）。

### 来源闸门

打开来源或已有本地权威摘录，核对人名、年代、数据、定理表述和引用范围；来源不可访问或不能定位原文的卡片标为 `unverified`，**不得进入正文**。历史事实不能只写搜索摘要，URL/书目信息、摘录或页码至少有一项可复核。

### 数学/教学闸门

独立重算例子和反例，检查定义域、量词、边界值、对象类型和前置闭合；用一句话回答“学生完成什么动作后会获得哪个判断”。不满足者标为 `rejected`。通过者标为 `approved`，并把卡片 ID、落点、功能和核验结论登记到 `coverage-map.md`。核验结论必须按来源类型写明具体证据：`REUSE-ORIGINAL` 写可定位锚点并说明复核了什么；`SELF-CONTAINED` 写数据与复算过程；`EXTERNAL` 写来源与相应摘录；不得只写“核验通过”。

主 Agent 只批准满足以下全部条件的卡片：在预算内；删去背景句后数学任务仍清楚；与已批准卡片不承担同一功能；不提前泄露后续定义或定理。超出预算时按“删重复材料 → 合并同功能卡片 → 缩短背景为一句 → 删除历史材料”顺序处理，**不能通过压缩字体或密集排版掩盖超长**。

## 阶段 D：整合为正文输入包（material-pack-secN.md）

主 Agent 不把整份研究文件原样塞入切片 prompt，而是为每个切片生成短的 `material-pack-secN.md`，只包含：

- 已批准（`approved`）卡片；
- 使用顺序；
- 不得泄露的结论；
- 最小前置定义；
- 与前后题的桥接句要求。

`sec0` 的材料包额外限制为叙述为主、最多 1–2 道进入题，并携带**开篇—首节入口约定**（学生已知与能做动作、开篇建立的观察、留下的未解问题、答案首次揭示位置、首节接续动作；见 `prompts/subagent_prompt.md` 开篇模板），首节材料包引用同一份约定。小节材料包要求材料必须导向明确题目，不得独立成“资料展示”。

### 机器索引 `.pd/materials.json`（F07 起）

材料包定稿后，用 `python scripts/evidence.py materials-index <project> --out <project>/.pd/materials.json` 由材料包已有证据整理生成机器索引（不替代原来源摘录）。每张卡片字段固定：`card_id`、`requirement_id`、`status`、`source_type`、`source_locator`（原文锚点/复算定位）、`verification_locator`（核验记录定位）、`used_by_qids`。`status` 按**精确相等**判断，只有 `approved` 可进入正文；`unapproved` 不会被子串误匹配为已批准。正文有 `% card:` 引用却无索引或材料包批准记录时 deliver 判失败；无卡片引用且计划明确无补充材料时允许空索引。切片中的卡片注释统一用独立行 `% card: CARD-xx`（旧版 `% qid: ... | card: CARD-xx` 合并行仍可被解析器识别，新写作不再输出）。来源和计算的内容真实性由审读判断，脚本只做一致性核对。

---

## 失败处理顺序

1. 先退回研究卡片补字段；
2. 仍不满足则换候选来源；
3. 再不满足则在 `research-gaps.md` 记录“本章不补材料”，由主 Agent 调整叙事锚点或删除该材料需求。

**禁止由切片 Agent 临时填空。**
